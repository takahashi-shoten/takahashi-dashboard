# AI自律収益化事業 — 経営原則(永続的な指針)

オーナー指示(2026-11-23)を保存したもの。今後の設計・開発・調査・企画・制作・運用・改善は、すべてこの原則に従う。

## 0. 最上位の原則
目的は「高品質な動画を作ること」でも「偶然の大ヒット」でもない。複数のAIと外部サービスを組み合わせ、**実験・失敗・分析・改善を自律的に繰り返し、継続利益を生む事業システムを作る**こと。
初回の収益化や大ヒットは要求しない。最初の重要な成果は、**実験と改善の循環が実際に機能すること**。
許容しないもの: 検証されない仮説 / 学習のない失敗 / 実験しないまま調査だけを続ける状態。

## 1. 人間の根本的欲求から市場を分析する
AIが思いついたテーマを、そのまま企画にしない。まず人間が何を欲し、何に悩み、何を解決したいかを分析する。
重点領域(これに限定しない。世界の市場を横断して新しい需要も発見する):
経済的欲求 / 自己実現 / 精神的欲求 / 美容・健康 / 恋愛・対人関係 / 娯楽・好奇心(驚き・笑い・感動・恐怖・謎・物語・知識欲) / 生活改善。
これらは**市場仮説**であり、需要・競争・収益性は実測で判断する。

## 2. 企画を決める前に確認・記録すること
1. 誰のどの欲求・問題か / 2. 強いと判断した根拠 / 3. 実際に視聴されている競合動画 / 4. 競合チャンネルの規模と通常投稿の再生分布 /
5. 個人+AIで対抗できる余地 / 6. 差別化できる切り口 / 7. 制作費・制作時間 / 8. 収益化の経路 / 9. この動画で何を検証するか / 10. 失敗時に原因分析に使う指標。
競合の動画URL・投稿日・再生数・登録者数・投稿頻度を残す。確認できない数値は推測で埋めず**未確認**とする。
制作会社の大ヒットは需要分析の参考にはなるが、個人AI事業の成功可能性の直接証拠にしない。
企画はAIが根拠に基づいて選ぶ。経営者に、根拠のない台本の良し悪しを毎回判断させない。

## 3. 実験と改善のサイクル(システムの中心)
市場調査 → 仮説 → 企画 → 制作 → 品質確認 → 公開 → 実績収集 → 原因分析 → 改善 → 再実験
各実験に一意のIDを付け、記録する: 仮説 / 対象視聴者 / タイトル・サムネ・構成・尺 / 使用AI・ツール / 制作費(API料金含む) / 制作時間 / 公開日時 /
インプレッション・CTR / 再生数・平均視聴時間・視聴維持率 / 登録者増加 / 売上・収益化状況 / 仮説と実績の差 / 次回変更する要素とその理由。
取得できない指標は**未取得**と記録。公開後24時間・72時間・7日・28日で、比較可能な形でデータを保存する。
分析では「再生されなかった」で終わらせない: 表示機会が少ない / クリックされない / 冒頭で離脱 / 内容が期待と違う、を区別する。
データ不足なら原因を断定せず、次の実験で切り分ける。一度に変える主要要素は絞る。

## 4. AIの役割分担(固定しない。費用と性能で選ぶ)
Claude Code=開発・実験管理・連携・制作パイプライン / ChatGPT=市場分析・仮説検証・企画の批判的評価 / Gemini等=映像・画像・音声・品質確認 /
GitHub=コード・実験データ・実行履歴 / Obsidian=事業知識・検証結果・意思決定 / YouTube Analytics等=公開後の実測。
同じAI同士の賛成意見を、市場需要の証拠とみなさない。最終評価は、実際の視聴者・顧客の行動。

## 5. 予算とリスク
月間予算は原則30,000円以内。予算は実験と学習のために使い、低コストだからという理由で効果のない調査・制作を続けない。
記録して評価する: 1本当たり制作費 / 1実験当たり費用 / 有効な学習1件当たり費用 / 継続制作時の予想費用 / 実際の売上と利益。
承認が必要: 新規課金・予算上限の変更・アカウント作成・公開権限の付与・**初回公開**。承認済み範囲内の反復作業は、毎回の判断を求めない仕組みを目指す。

## 6. 開発方針
既存資産(リポジトリ・ブランチ・PR・研究DB・制作パイプライン・Actions・API設定・テスト)を破棄しない。まず現状を実際に確認する。未完成を完成と報告しない。
最優先は、**小さな実験を実際に市場へ出し、結果を次の制作に反映できる最小の閉ループを完成させる**こと。大規模なシステムを最初から作らない。最初は一部手動でよい。

## 7. 自律性と報告
経営者は毎回、テーマや台本を選ぶために参加しない。AIが調査・判断・実験・失敗分析を進める。
報告は: 完了・実行したこと / 実測結果 / 失敗と原因 / 次に変更する要素 / 使用費用 / 承認が必要な事項。
「これから調査します」「このジャンルが有望です」だけを成果としない。実行できないことは明示する。障害時は、権限と予算の範囲内で代替手段を探して継続する。
台本を経営者に丸投げせず、企画選定の根拠・検証仮説・想定費用を明示する。
