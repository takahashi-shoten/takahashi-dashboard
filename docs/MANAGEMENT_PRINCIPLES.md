# AI自律収益化事業 — 経営原則(永続的な指針)

オーナー指示(2026-11-23)を保存したもの。今後の設計・開発・調査・企画・制作・運用・改善は、すべてこの原則に従う。

## 0. 最上位の原則
目的は「高品質な動画を作ること」でも「偶然の大ヒット」でもない。複数のAIと外部サービスを組み合わせ、**実験・失敗・分析・改善を自律的に繰り返し、継続利益を生む事業システムを作る**こと。
初回の収益化や大ヒットは要求しない。最初の重要な成果は、**実験と改善の循環が実際に機能すること**。
許容しないもの: 検証されない仮説 / 学習のない失敗 / 実験しないまま調査だけを続ける状態。

## 1. 人間の根本的欲求から市場を分析する
AIが思いついたテーマを、そのまま企画にしない。まず人間が何を欲し、何に悩み、何を解決したいかを分析する。
重点領域(これに限定しない。世界の市場を横断して新しい需要も発見する):
経済的欲求 / 自己実現 / 精神的欲求 / 美容・健康 / 恋愛・対人関係 / 娯楽・好奇心(驚き・笑い・感動・恐怖・謎・物語・知識欲) / 生活改善。
これらは**市場仮説**であり、需要・競争・収益性は実測で判断する。

## 2. 企画を決める前に確認・記録すること
1. 誰のどの欲求・問題か / 2. 強いと判断した根拠 / 3. 実際に視聴されている競合動画 / 4. 競合チャンネルの規模と通常投稿の再生分布 /
5. 個人+AIで対抗できる余地 / 6. 差別化できる切り口 / 7. 制作費・制作時間 / 8. 収益化の経路 / 9. この動画で何を検証するか / 10. 失敗時に原因分析に使う指標。
競合の動画URL・投稿日・再生数・登録者数・投稿頻度を残す。確認できない数値は推測で埋めず**未確認**とする。
制作会社の大ヒットは需要分析の参考にはなるが、個人AI事業の成功可能性の直接証拠にしない。
企画はAIが根拠に基づいて選ぶ。経営者に、根拠のない台本の良し悪しを毎回判断させない。

## 3. 実験と改善のサイクル(システムの中心)
市場調査 → 仮説 → 企画 → 制作 → 品質確認 → 公開 → 実績収集 → 原因分析 → 改善 → 再実験
各実験に一意のIDを付け、記録する: 仮説 / 対象視聴者 / タイトル・サムネ・構成・尺 / 使用AI・ツール / 制作費(API料金含む) / 制作時間 / 公開日時 /
インプレッション・CTR / 再生数・平均視聴時間・視聴維持率 / 登録者増加 / 売上・収益化状況 / 仮説と実績の差 / 次回変更する要素とその理由。
取得できない指標は**未取得**と記録。公開後24時間・72時間・7日・28日で、比較可能な形でデータを保存する。
分析では「再生されなかった」で終わらせない: 表示機会が少ない / クリックされない / 冒頭で離脱 / 内容が期待と違う、を区別する。
データ不足なら原因を断定せず、次の実験で切り分ける。一度に変える主要要素は絞る。

## 4. AIの役割分担(固定しない。費用と性能で選ぶ)
Claude Code=開発・実験管理・連携・制作パイプライン / ChatGPT=市場分析・仮説検証・企画の批判的評価 / Gemini等=映像・画像・音声・品質確認 /
GitHub=コード・実験データ・実行履歴 / Obsidian=事業知識・検証結果・意思決定 / YouTube Analytics等=公開後の実測。
同じAI同士の賛成意見を、市場需要の証拠とみなさない。最終評価は、実際の視聴者・顧客の行動。

## 5. 予算とリスク
月間予算は原則30,000円以内。予算は実験と学習のために使い、低コストだからという理由で効果のない調査・制作を続けない。
記録して評価する: 1本当たり制作費 / 1実験当たり費用 / 有効な学習1件当たり費用 / 継続制作時の予想費用 / 実際の売上と利益。
承認が必要: 新規課金・予算上限の変更・アカウント作成・公開権限の付与・**初回公開**。承認済み範囲内の反復作業は、毎回の判断を求めない仕組みを目指す。

## 6. 開発方針
既存資産(リポジトリ・ブランチ・PR・研究DB・制作パイプライン・Actions・API設定・テスト)を破棄しない。まず現状を実際に確認する。未完成を完成と報告しない。
最優先は、**小さな実験を実際に市場へ出し、結果を次の制作に反映できる最小の閉ループを完成させる**こと。大規模なシステムを最初から作らない。最初は一部手動でよい。

## 7. 自律性と報告
経営者は毎回、テーマや台本を選ぶために参加しない。AIが調査・判断・実験・失敗分析を進める。
報告は: 完了・実行したこと / 実測結果 / 失敗と原因 / 次に変更する要素 / 使用費用 / 承認が必要な事項。
「これから調査します」「このジャンルが有望です」だけを成果としない。実行できないことは明示する。障害時は、権限と予算の範囲内で代替手段を探して継続する。
台本を経営者に丸投げせず、企画選定の根拠・検証仮説・想定費用を明示する。

## 8. 追加方針(2026-11-24 統合実行指示書)
`CLAUDE.md` の "Directive of 2026-11-24" に要約。要点: 他者の成功・失敗の過程から再利用可能な原理を学ぶ / 実際の動画(映像+音声)を解析する能力を、正解のあるテストで実証してから大量解析に進む /
制作者と評価者を分離し評価AIの精度も検証する / 知識はSQLiteに永続保存し自動検索・市場結果で更新 / YouTube以外も含め収益化手段を比較 / 各機能の状態を6段階で記録 / 根拠のない達成率を報告しない。

## 9. 実際の商取引の調査と、人の所得を増やす価値(2026-11-26 追加方針。既存の原則を破棄しない)
- **市場調査の対象を拡張する**: YouTube(関心・集客の研究)に加え、世界の**実際の商取引**(ココナラ、Gumroad、Etsy、BOOTH、note、Fiverr/Upwork、Udemy、Kindle、アプリストア、Kickstarter、Product Hunt、itch.io、SaaS、AIエージェント市場、SNS直販ほか)を調べる。再生数・フォロワー数でなく、お金が動いた事実で見る。規模は千→万→十万→百万件を目指すが、**件数は目標でなく、事業機会の発見が目的**。百万件に達するまで市場実験を待たない。公式API・公開データ・許可された収集・既存データセットを使い、通常のプログラム・SQL・統計・低コストモデルで処理し、高価なモデルは判断に限る。
- **区別する**: 自己申告 / レビュー数 / 順位 / 推定売上 / 確認できた売上。**支援表明額と決済確定額、売上と利益**。観察した事実・AIの解釈・仮説。取得できないものは未確認。売れなかったものも調べる。出典URL・観測日時・証拠の信頼性を残す。
- **なぜ払うのかを理解する**: 購入者が欲しいのは商品そのものでなく、収入・自由・生活の改善・「自分にもできる」という期待であることが多い。この欲求と購買行動の関係を研究し、表面の模倣でなく、背後の需要を見つけて**本当に価値のある商品・サービス**に転換する。収益保証、価値の乏しい高額商品は扱わない。
- **経営思想(参考例。特定人物は決定ではない)**: 「自分が金持ちになる近道は、人を金持ちにすること」。人の所得を増やす・支出を減らす・時間を生む商品とサービス(AIが実務を担うものを含む)を重点的に研究する。ただし、より有望な市場があれば客観的に比較して切り替える。
- **統合する能力**: 売れているものを発見する / 払う理由を理解する / 不足・不満を発見する / AIで価値ある商品を作る / 価値を伝える / 顧客を獲得する / 販売する / 利益を測る / 結果から改善する / 事業機会を発見し続ける。
- **知識の扱い**: データを集めても、無条件にAIへ与えて能力が上がるとは限らない(比較試験の結果)。データ・事実・仮説・知識・実務への応用・市場検証を区別し、AI本来の推論力を保ちつつ、市場データで判断の精度を高める。
- **既存の方針との関係(矛盾の整理)**: 「最終的な月100万円」は、11-25 の明確化のとおり**通過点**(5年で純資産1億円)で、12/20 は最初の区切り。調査規模の目標は、「知識・データの件数を増やすこと自体を目標にしない」(11-26)と両立する(件数は手段)。予算(月3万円、研究API 2,000円)と承認条件(外部公開・新規契約・追加課金・設定変更・ネットワーク許可の追加は承認)は維持。この追加で、サロン・動画制作・マーケ学習・知識活用の作業は中断しない。
- 詳細・結果: `docs/research/commerce_data_survey_2026-11-26.md`。

## 10. 最重要経営原則: 市場浸透と複利型収益成長(2026-11-27 オーナー指示・恒久。正本はこの節。親・子プロジェクト共通)
今後のすべての経営判断・商品設計・価格設定・マーケティング・販売戦略に反映する。
1. **単利的な思考をしない**: 「顧客数×単価を毎月繰り返す」計算は、現在の収益構造の把握には要るが、将来の成長の評価には不十分。事業活動を繰り返すたびに経営資産が蓄積し、次の収益獲得が容易になり、成長速度が加速する複利型を目指す。
2. **複利とは**(利益の再投資だけではない。以下がすべて蓄積し、相互に作用する): 顧客 / 継続契約の収益 / 成功事例・実績 / 信用・ブランド認知 / 口コミ・紹介 / 市場データ・顧客理解 / マーケティング能力 / セールスコピー能力 / 制作技術・自動化能力 / 商品・サービス / 利益・再投資資金。例: 最初の顧客の経験が次の獲得に役立つ。最初の10本が次の100本の効率と品質を上げる。最初の成功事例が営業材料になる。顧客から得た情報が新商品につながる。
3. **市場浸透**: 顧客に継続してもらうだけではない。商品・サービスが認知され、利用され、評価され、紹介され、市場での存在感と信用が高まること。最初は1店舗でよい。その店で成果を出し営業材料にし、次の店でさらに成果を出す。既存顧客への価値提供・新規顧客の獲得・商品価値の向上を同時に進める。(毎週の数字を見せること・制作時間を削ることは構成要素の一部にすぎない。)
4. **初期の価格**: 低い初期価格(例: リール1本2,000円)は、参入・顧客獲得・実績と信用づくりのための**戦略的な価格として検証する**。将来にわたる固定価格ではない。初期の利益が小さいことだけを理由に事業の可能性を否定しない。同時に、安売りの継続を目的にしない。実績・商品価値・需要に応じて、価格改定・月額契約・上位サービス・関連商品を検討する。**初期の低価格が将来の収益につながっているかを実測する**。
5. **商品を1つに限定しない**: 最初の商品が何であれ、顧客が何に困り何にお金を払うかを学び続け、**需要と支払い意思が確認された領域**(集客・予約・顧客維持・SNS運用・販促・業務効率化など)へ発展させる。顧客が専門知識を学ばないと使えない商品より、少ない手間で目的を達成できる仕組みを重視する。ただし新商品は、思いつくたびに作らず、需要と支払い意思を確認してから実行する。
6. **成長は直線で考えない**: 親(AI自律収益化)の目標は1年で月間利益100万円(Q1 月10万 / Q2 月30万 / Q3 月60万 / Q4 月100万。上積み10/20/30/40万)。これは**AI収益化事業全体**の目標で、美容業界事業単独のノルマではない。複利は自然に起きると仮定せず、**起きる仕組みを設計し、測定し、改善する**。
7. **AIによる複利**: 人間が同じ仕事を繰り返す事業は、人の作業量が成長の限界になる。顧客が増えるほど市場データ・実績が増え、実験を重ねるほど効く手法が明確になり、制作を重ねるほど構成・工程が蓄積して自動化の精度が上がる。→ 品質向上、原価削減、獲得費用削減、販売力向上。顧客10倍で人の仕事も10倍にならない事業を目指す。
8. **経営判断の基準**(現在の利益だけでなく変化を見る): 新規顧客数と継続顧客数 / 紹介による獲得 / 顧客あたりの売上と利益 / 顧客獲得費用 / 顧客満足度と実際の成果 / 商品価値と販売力 / 制作原価と人の作業時間の削減 / 新しい収益機会 / 再利用できる知識・技術の蓄積。売上が小さくても資産が増えているかを評価する。逆に、売上が増えても人的負担や獲得費用が比例して増え続けるなら、収益構造を改善する。
9. **記録と運用**: この節を正本とし、`CLAUDE.md`(開始時に必ず読まれる)には要点と参照、`docs/DECISIONS.md` には指示の記録のみを置く(本文の重複はしない)。親・子で共有する。
10. **既存作業への適用**: 既存の調査・制作技術は捨てず、大規模改修もしない。目的は理論の完成ではなく、複利的に利益が拡大する事業を実際に成立させること。
- 注意(運用): 事業の評価で「必要店数=目標利益÷1店の利益」のような均等割りだけを根拠にしない(現在の構造の把握としてのみ使い、将来評価と区別して書く)。
